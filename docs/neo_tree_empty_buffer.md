# Neo-tree 空白缓冲区排查

日期：2026-11-10（东八区）。

## 目标与约定

用户选择保留左侧文件树，打开文件后自动清理多余的空白缓冲区。
启动时右侧仍是编辑占位窗口；从树中正常打开文件后复用该窗口。
不自动删除有内容、已修改或仍显示在窗口中的缓冲区，不使用强制删除。

## 排查过程与结论

1. 使用当前配置启动 `nvim --headless -i NONE .`，检查窗口和缓冲区。
   Neo-tree 创建了一个列入缓冲区列表的普通未命名缓冲区，`modified=false`。
   `:q` 正常执行；用户随后确认没有退出报错，关注的是占位缓冲区多余。
2. 在 `/tmp` 使用临时 Lua 驱动正常启动、定位 README.md、调用 Neo-tree
   的文件打开命令。打开前有一个空白缓冲区；打开后文件复用右侧窗口，
   但空白缓冲区仍列在列表中，已没有对应窗口。
3. 检查本机插件源码：`setup/netrw.lua` 接管目录时通过
   `nvim_create_buf(true, false)` 创建占位缓冲区；`utils/init.lua` 打开文件时
   使用 `bufadd` 后切换缓冲区。结合本配置的 `hidden=true`，原缓冲区被保留。
   这是插件打开流程与缓冲区保留机制组合造成的体验问题。
4. 通过 Context7 查询 Neovim 官方文档，核对 `hidden`、退出和缓冲区删除行为；
   通过已安装 Neo-tree 的文档核对 `file_opened` 事件。

## 实现与验证

在 `lua/plugins/layout.lua` 中注册 `file_opened` 事件，仅清理已加载、列入列表、
普通类型、未命名、未修改、无可见窗口且只有一行空字符串的缓冲区。

使用完整配置执行临时验证（缓存和日志重定向到 `/tmp`）：

- 普通打开文件：残留空白缓冲区从 1 个降为 0 个；文件树保留，文件正常打开。
- 未命名缓冲区含未保存文字：保留。
- 未命名缓冲区有内容但 `modified=false`：保留。
- 从树中垂直分屏打开文件：仍显示在原窗口中的空白缓冲区保留。

未新增仓库测试文件。重启 Neovim 后生效。

## 补充：只浏览目录时一次退出

用户补充要求：打开目录但没有打开文件时，执行一次 `:q` 同时退出文件树和
空白窗口，无需退出两次。

1. 修复前，完整配置启动后焦点在文件树，执行 `:q` 后进程仍运行，留下空白窗口。
2. 查询 Context7 文档并检查本机 Neo-tree 实现。内置 `close_if_last_window`
   只处理关闭编辑窗口后剩下文件树的方向，不能解决从文件树执行 `:q` 的情况。
3. 在 Neo-tree 初始化时注册 `QuitPre`：仅当唯一标签页里恰好是文件树和
   未修改的空白窗口，且没有其他列入列表的缓冲区或任何已修改缓冲区时，
   先非强制关闭另一个窗口，再由原来的 `:q` 完成退出。
4. 临时脚本通过完整配置验证：分别从文件树和空白窗口执行一次 `:q`，进程均
   正常退出，退出码为 0。含未保存文字、隐藏的未保存文字、其他已列入列表的
   文件缓冲区或其他标签页时，不触发联动退出，内容保留。
5. `:close` 不触发此规则，仍可单独关闭文件树。`git diff --check` 通过。
